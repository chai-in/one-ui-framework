# One UI design review

The review followed three tasks through the library: find a component and use it, edit a draft and recover from a mistake, and read the value behind a chart. The same actions were examined in the Web Components, React and native controls wherever an equivalent control exists.

| Research | What it changed in One UI |
| --- | --- |
| Apple emphasizes recognizable controls and hierarchy. Fluent uses proximity to show which information belongs together. [Apple design principles](https://developer.apple.com/design/human-interface-guidelines/design-principles/) · [Fluent layout](https://fluent2.microsoft.design/layout) | The playground puts the draft title, saved state and commit actions together. Search, active category and result count share one wrapping toolbar. Preview preferences collapse into a disclosure. |
| USWDS reserves cards for independently meaningful items. Carbon treats an empty search result as a recoverable state with a distinct cause. [USWDS cards](https://designsystem.digital.gov/components/card/) · [Carbon empty states](https://www.carbondesignsystem.com/building-blocks/core/patterns/empty-states) | The component collection uses a quiet, aligned grid. One surviving search result retains the width of its peers. Clearing an empty filter restores the collection and returns focus to search. |
| GOV.UK keeps valid input after failed submission and associates the problem with the field. [GOV.UK validation](https://design-system.service.gov.uk/patterns/validation/) | A blank draft title exposes an inline error. Discard restores the last saved title. Cancelling a deletion preserves the draft and returns focus to its trigger. |
| The UK Analysis Function describes how to compare quantitative data. W3C provides examples of structured data alternatives for charts. [Chart guidance](https://analysisfunction.civilservice.gov.uk/policy-store/data-visualisation-charts/) · [W3C complex images](https://www.w3.org/WAI/tutorials/images/complex/) | Spring presets share a time axis. The figure gives settle time and overshoot, and its disclosure exposes the sampled values as a native table with units. Numeric columns share an end edge and tabular figures. |
| Impeccable distinguishes visual critique from source inspection. Vercel emphasizes interaction details such as stable geometry. [Impeccable critique](https://github.com/pbakaus/impeccable/blob/main/skill/reference/critique.md) · [Vercel interface guidelines](https://vercel.com/design/guidelines) | Rendering an actual 520px catalog exposed three overflowing sliders despite a clean source audit. Their intrinsic-width fix lives in the shared component CSS. |
| WAI-ARIA describes the arrow keys for each tab orientation, keyboard behavior for menus and the destination of focus after a dialog closes. [Tabs](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/) · [Menu button](https://www.w3.org/WAI/ARIA/apg/patterns/menu-button/) · [Modal dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) | Tabs respect orientation and inherited text direction. A menu with no available commands stays closed. A dialog remembers the control that invoked it even when pointer activation left focus elsewhere. |
| Apple describes progress and Android documents minimum sizes for touch interactions. Flutter supplies native button semantics. [Apple progress indicators](https://developer.apple.com/design/human-interface-guidelines/progress-indicators/) · [Compose accessibility defaults](https://developer.android.com/develop/ui/compose/accessibility/api-defaults) · [Flutter accessibility](https://docs.flutter.dev/ui/accessibility) | Native loading buttons retain their label and geometry. An unknown progress value stays indeterminate under reduced motion. SwiftUI lets the application acknowledge a successful send. |

## Where visual restraint helped

Removing the repeated card chrome left each moment's actual control as its identifying preview. Keeping the spring plot *and* a data table was a different decision. A curve answers “which spring overshoots?” while the table answers “where was it at this time?” Removing the table would make the second question harder to answer and lose the equivalent reading route.

Two changes belong in the distributed system. The responsive toolbar, collection and table styles are available through the Web package, React styles and CLI-installed CSS. The explicit High Contrast preset now supplies the same stronger field edges and focus width in consuming applications that the showcase had to implement locally.

## Prior verification observations

- The full repository check passed 259 JavaScript and TypeScript tests, 8 SwiftPM tests and all 750 declared color comparisons. The static auditor covered 32 files.
- Headless Chromium exercised the catalog at 320, 375, 520, 768, 1024, 1440 and 1600 CSS px. Keyboard tests covered blank-title recovery, cancelling deletion, resetting an empty filter, restoring dialog focus, and dismissing nested overlays across React and a shadow root. The zoom check used 200% CSS zoom with forced colors, dark appearance and reduced motion emulated.
- In an isolated 242px-wide RTL container a 1200px table scrolled within its region. The surrounding collection stayed at 242px. Computed field edges were 2px in an explicit High Contrast scope and 1px in a nested default scope. Filled actions followed the border setting in both.
- SwiftUI passed iOS and watchOS target typechecks. Flutter 3.35.5 passed analysis and three isolated widget tests covering loading geometry, keyboard focus and indeterminate progress.
- All four Android source files compiled against Android SDK 35 revision 2, Compose 1.8.2 and Material 3 1.3.2. Kotlin and its Compose compiler plugin were both 2.1.21. The build targeted JVM 17, treated warnings as errors and produced 27 classes. This covered library compilation. Android APK, emulator and TalkBack runs are outside this result.
- Firefox 153.0 and Playwright WebKit 26.5 passed the catalog, keyboard focus and recovery, draft, clipboard, chart and contrast scenarios, seven viewport widths and 200% CSS zoom.
- Desktop Safari 27.2 on a GitHub-hosted Mac passed catalog filtering, keyboard activation, draft save and cancellation, dialog Escape and focus return, theme changes, and seven embedded viewport widths. The reflow check measured overflow against the available content width after the native scrollbar.
